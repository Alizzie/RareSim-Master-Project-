# Data and Storage Lifecycle

## Purpose

Caches and artifacts get described separately as they come up across the Artifacts and Evaluation sections. This page collects them into one lifecycle view.

## The Pattern

Across almost every row below, the direction of flow is the same: raw or upstream data is transformed **once** into a derived artifact, and that artifact is **read-only** for everything downstream of it.

The one deliberate exception is the **per-case evaluation cache**, which is additive by design — so a newly implemented method can be layered onto existing cached cases without rerunning or deleting anything already there. See [Cache Format](/evaluation/cache-format) for the exact merge mechanics.

## Lifecycle Table

| Data | Location | Produced by | Lifecycle |
|---|---|---|---|
| Raw ontology and annotation files | `data/ontologies/` | `load_ontologies_to_local.py` | Downloaded once; re-downloaded only when source versions change. |
| Generated artifacts | `outputs/artifacts/*.json` | `build_shared_artifacts.py` | Built once from raw files; read-only at runtime. |
| Model caches (autoencoder, HPO2Vec) | `MODEL_CACHE_DIR` per method | `load_or_train()` in each pipeline | Trained once per hyperparameter + vocabulary fingerprint, then reused. |
| Benchmark datasets | `data/datasets/.../standardized/` | Per-source standardization scripts | Built once per dataset release; read-only afterward. See [Benchmark Dataset Standardization](/evaluation/benchmark-dataset-standardization). |
| Per-case evaluation cache | `outputs/evaluation/<DATASET>/cache/` | Batch runners; results merged additively | Updated incrementally, one method's entries at a time. |
| Evaluation reports | `outputs/evaluation/<DATASET>/*.json, *.txt, *.tsv` | `evaluator.py` | Fully regenerated every time the evaluator runs. |
| Validation tool caches | `outputs/validation_tools/<TOOL_NAME>/cache/` | `run_<tool_name>.py` | Generated by the tool-specific runner; updated when that tool runs. |
| Validation metrics and comparisons | `outputs/validation_tools/<TOOL_NAME>/*.txt, *.tsv` | `compare_methods.py` | Regenerated from cached validation results whenever the comparison script runs. |
| Interactive runtime cache | Timestamped file per patient case | Backend and core pipeline | Written once per interactive diagnosis. |
