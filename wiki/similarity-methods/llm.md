# LLM Method

## Overview

The LLM method is a prompt-based rare disease retrieval and explanation pipeline.

It does not compute embedding similarity and it does not use HPO graph similarity for scoring. Instead, it directly asks a generative language model to suggest likely rare diseases from a patient's clinical text and direct HPO phenotype labels.

Current model:

```text
mistralai/Mistral-7B-Instruct-v0.2
```

The method has two main steps:

1. **Direct retrieval**: the LLM receives the patient profile and generates a list of likely rare diseases.
2. **Explanation**: the LLM receives a patient-disease pair and explains why the disease may or may not fit the patient.


## Pipeline Flow

```text
PatientProfile
    ↓
Build prompt from raw text + direct HPO labels
    ↓
Query HuggingFace LLM
    ↓
Parse generated disease list
    ↓
Validate generated diseases against local disease profiles
    ↓
Convert confidence label to numeric score
    ↓
Create SimilarityResult objects
    ↓
Generate explanations for top candidates
    ↓
Return ranked LLM results
```

The important difference from transformer methods is that the LLM does not compare the patient against every disease embedding. It generates candidate diseases directly from the prompt.


## Input

The LLM method uses:

```text
Patient raw clinical text
Direct patient HPO terms
HPO labels
```

It uses direct HPO terms only:

```python
patient.get_terms(use_propagated=False)
```

So propagated HPO terms are not used in this method.


## Output

The method returns standard `SimilarityResult` objects.

Each result contains:

```text
disease_id
label
score
method_name
rank
matched_aliases
category metadata
explanation
```

The score is based on the LLM's confidence label, not on an embedding score or HPO similarity score.

Example score mapping:

```text
high / strong      -> 0.9
medium / possible  -> 0.6
low / weak         -> 0.3
unlikely           -> 0.1
unknown            -> 0.5
```


# File Roles

## config.py

Stores configuration for the LLM pipeline.

Main contents:

```text
PIPELINE_NAME
LLM_DIR
LLM_MODEL_LIST
EXPLAINER_MODEL
generation settings
top-k settings
confidence-to-score mappings
```

Important settings:

```python
MAX_NEW_TOKENS_RETRIEVAL = 2048
MAX_NEW_TOKENS_EXPLAINER = 1024
TEMPERATURE = 0.1
DO_SAMPLE = True
REPETITION_PENALTY = 1.3
TOP_K = 10
TOP_K_RERANK = 10
```

The confidence labels generated by the LLM are mapped to numeric scores using `MATCH_LEVEL_SCORES` and `MATCH_LEVEL_ALIASES`.


## methods.py

Contains low-level helper functions for model loading, prompt construction, output parsing, and explanation parsing.

### Helper functions

`as_string_list(value)` converts list-like values into a list of strings.

`merge_aliases(*alias_groups)` merges multiple alias groups into one sorted unique list.

`get_hpo_label(term, hpo_labels)` returns the readable HPO label for an HPO ID. If no label is found, it returns the HPO ID.

`confidence_to_score(confidence)` converts LLM confidence text into a numeric score.

### HuggingFace backend

`load_hf_pipeline(model_name, max_new_tokens)` loads a HuggingFace text-generation pipeline. It first tries 4-bit quantization and falls back to float16 if needed.

`unload_pipeline(pipe)` releases GPU memory after the model is done.

`query_hf(prompt, pipe, max_tokens)` sends a prompt to the loaded LLM and returns only the generated text, removing the original prompt from the output.

### Text and prompt building

`build_patient_context_text(patient, hpo_labels)` builds readable patient text from raw clinical text and direct HPO labels.

`build_disease_text_preview(disease_profile, fallback_label, hpo_labels)` builds a short disease preview for explanations.

`build_retrieval_prompt(patient, hpo_labels, top_k)` creates the main prompt for direct disease retrieval. It asks the LLM to list exactly `top_k` diseases in this format:

```text
DISEASE: <name> | ORDO: ORPHA:<number> | MATCH: <phenotypes> | CONFIDENCE: <high/medium/low>
```

`build_explanation_prompt(...)` creates a second prompt for explaining one candidate disease. It includes patient phenotypes, disease phenotypes, disease description, rank, score, and direct phenotype overlap.

### Parsing functions

`find_disease_in_profiles(ordo_id, disease_name, disease_profiles)` tries to match a generated disease to the local disease profile database. It checks exact ID match, normalized ID match, and name match.

`parse_retrieval_output(...)` converts raw LLM retrieval output into SimilarityResult objects and attaches a standardized explanation object containing method-specific metadata and diagnostics.

`parse_explanation(generated_text)` parses the LLM's clinical explanation into:

```text
reasoning
verdict
verdict_reason
text
```

If the model does not follow the expected format, it falls back to a short text summary.


## explanation.py

Builds standardized explanations for LLM results.

`build_method_specific_explanation_block(...)` stores LLM-specific explanation metadata, including model name, prompt name, confidence, matched phenotypes, patient text preview, disease text preview, and LLM response preview.

It also records that the LLM method does not use:

```text
IC values
dense embeddings
direct HPO overlap for scoring
```

`build_explanation(...)` wraps the LLM-specific explanation inside the shared RareSim explanation format. Shared HPO terms may be shown for readability, but they do not drive the LLM score.


## retriever.py

Contains the high-level `LlmDiseaseRetriever` class.

`__init__(...)` stores the patient, HPO labels, disease profiles, IC values, disease ancestors, and disease metadata.

`from_context(patient, context)` creates a retriever from `AppContext`, so the pipeline does not need to pass every shared artifact manually.

`retrieve_with_pipe(pipe, model_name, top_k)` performs direct LLM retrieval:

```text
build retrieval prompt
query LLM
print raw output
parse generated diseases
validate diseases against profiles
return SimilarityResult list
```

`explain_results_with_pipe(pipe, candidate_results, ...)` generates clinical explanations for the top candidate results. It builds explanation prompts, queries the LLM in batch, parses the explanation output, and adds fields such as:

```text
clinical_explanation
verdict
verdict_reason
explainer_model
```

`run_stats(rankings, elapsed)` builds standard run statistics. Since the LLM only generates candidates, `n_diseases_scored` is the number of returned results, not the number of all diseases in the database.


## pipeline.py

Connects the LLM method to the shared RareSim pipeline runner.

`run(patient, selected, config, ctx)` runs the LLM method for each selected model.

For each model, it:

```text
loads the HuggingFace pipeline
runs direct retrieval
generates explanations for top results
unloads the model
builds run statistics
sorts and ranks results
returns MethodResults
```

`main()` allows the LLM pipeline to run from the command line through the shared `run_similarity_method(...)` entry point.


# Interpretation Notes

The LLM score is not a calibrated probability.

For example:

```text
CONFIDENCE: high -> 0.9
```

does not mean the disease has a 90% probability of being correct. It only means the model expressed high confidence.

The model can hallucinate disease names or IDs, so generated diseases are validated against the local disease profile database.

A result with:

```text
validated_against_profiles = True
```

means the generated disease was found locally.

A result with:

```text
validated_against_profiles = False
```

means the generated disease could not be matched to the local profiles.


# Difference from Transformer Method

Transformer method:

```text
patient text -> embedding
disease text -> embedding
score = cosine similarity
```

LLM method:

```text
patient text + HPO labels -> prompt
LLM generates diseases
parser extracts diseases
confidence label becomes score
```

So the LLM method is generative and prompt-based, while the transformer method is embedding-based.


# Summary

The LLM method directly asks a generative model to retrieve rare diseases from patient text and direct HPO labels. The generated disease list is parsed, validated, scored using confidence labels, and converted into standard RareSim results. The same model can also generate clinical explanations for top candidates.

The score is not based on embeddings, information content, or direct HPO overlap. It is based on the LLM's generated confidence level.
